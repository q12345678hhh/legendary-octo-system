# 职责分离与角色表

| 项目 | 内容 |
|---|---|
| 任务 | T00-01-3 |
| 要求 | 每个职责分离角色必须有真实人员，不得以「以后再定」通过 G1 |
| 当前状态 | **5 个角色全部空缺，G1 阻塞项** |

## 1. 必须指定的角色

| 角色 | 职责 | 不能兼任 | 责任人 | 状态 |
|---|---|---|---|---|
| 计划批准人 | 批准范围、工期、变更与门禁结论 | 不能同时承担安全复核 | （待指定） | 空缺 |
| 老板受托人 | 代表业务方裁决权限、特殊启用复核与跨部门冲突 | 不能同时是部门主管代表 | （待指定） | 空缺 |
| HR/薪酬专家 | 复核 HR 规则、薪酬算例、地域与合规口径 | 不能由开发者兼任 | （待指定） | 空缺 |
| 安全隐私复核人 | 复核威胁模型、DPIA、删除请求与事件处置 | 不能同时是计划批准人 | （待指定） | 空缺 |
| 部门主管代表 | 代表使用方确认工作页、审批链与试点反馈 | 不能同时是老板受托人 | （待指定） | 空缺 |
| 试点员工 | 自愿参与工作助手试点 | 需本人书面同意 | （待招募，5–10 人） | 空缺 |

## 2. 利益冲突检查

指定人员后必须逐条确认：

1. 同一人不得同时持有「提出变更」与「批准变更」两类角色。
2. 薪酬与 HR 规则的最终确认不得由开发实现者签字。
3. 安全事件的定级不得由被评估模块的负责人单独判定。
4. 老板受托人不得直接审批自己发起的特殊启用。
5. 试点员工的绩效评价人不得参与其试点数据的解释。

## 3. 缺席时的处理

| 角色 | 缺席后果 | 降级方案 |
|---|---|---|
| 计划批准人 | 不得进入任何门禁 | 无。G 门禁必须有人签字 |
| 老板受托人 | Phase 3 模块申请与特殊启用不得开放 | 无 |
| HR/薪酬专家 | Phase 7–8 不得开始，薪酬影子运行不得启动 | 无，不得以开发者判断替代 |
| 安全隐私复核人 | Phase 4 不得开始，真实数据采集不得启动 | 无 |
| 部门主管代表 | Phase 3 交付不得验收，只能内部演示 | 可延后，但不得计入完成 |
| 试点员工 | 工作助手只能做合成数据验证 | 可延后，但不得宣称试点通过 |

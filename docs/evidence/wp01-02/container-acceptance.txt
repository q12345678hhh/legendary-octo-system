三、端到端：请求 → outbox → Worker（贯穿 trace_id）
----------------------------------------------------
命令     POST http://localhost:8080/api/v1/system/smoke/ping-events
         X-Tenant-Id: 11111111-1111-1111-1111-111111111111
         X-Correlation-Id: corr-container-1
         X-Trace-Id: 0123456789abcdef0123456789abcdef
期望     201，响应回写关联头；outbox 落 pending 后转 published；Worker 日志带着同样的 id
实际
```
HTTP/1.1 201
X-Correlation-Id: corr-container-1
X-Trace-Id: 0123456789abcdef0123456789abcdef
{"traceId":"0123456789abcdef0123456789abcdef","correlationId":"corr-container-1",
 "tenantId":"11111111-1111-1111-1111-111111111111","eventId":"56e57ea9-7dca-4487-9cb1-8089380b45be"}

outbox: platform.smoke.ping.v1|published|1|platform-api|corr-container-1|0123456789abcdef0123456789abcdef

worker:
SmokePingEventHandler : 冒烟事件已收到 eventId=56e57ea9-… tenantId=1111… correlationId=corr-container-1
                        traceId=0123456789abcdef0123456789abcdef
OutboxDispatcher      : 事件已消费 event=platform.smoke.ping.v1 eventId=56e57ea9-…
                        correlationId=corr-container-1 traceId=0123456789abcdef0123456789abcdef
```
结论     通过。一次请求在 API 写库、同事务写 outbox、Worker 认领并消费，整条链路的
         correlation_id 与 trace_id 未断。

四、容器化前的准备路径
----------------------
- 镜像只搬运构建产物，缺件的判定与补齐在 scripts/dev-up.ps1 的 Ensure-AppArtifacts：
  缺 boot-api / boot-worker 的 jar 时执行 mvn -pl <模块> -am package -DskipTests；
  缺 frontend/apps/web/dist 时执行 pnpm --filter @platform/web build。
- 这样本地、CI 与容器用同一份 jar 与 dist，容器构建不需要再下载一遍依赖。

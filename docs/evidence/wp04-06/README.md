# WP04-06 试点与 G4 评审（执行包）

状态：**待执行真实试点**。本目录先固定试点范围、指标口径、周复核流程与签字清单；
合成数据只能验证口径，不能作为「连续四周真实运行」的 G4 证据。

## 1. 试点范围与节奏

- 对象：5–10 名自愿员工，覆盖主管、普通员工与财务复核角色；书面告知采集范围，
  可随时退出，退出不影响绩效。
- 边界：只用语音/文字工时、周报、单据上传与复核；不做设备监控、屏幕采集、
  键盘记录或定位追踪。
- 周期：连续四周，另加一周准备。
  - W0：账号与组织数据核对、隐私说明签署、10 分钟操作培训、确定周会时间。
  - W1–W4：真实使用；每周五导出指标并做 30 分钟访谈。
- 每周固定动作：
  1. 运行 `scripts/pilot-g4-metrics.sql` 导出四项自动指标；
  2. 抽样 10 张单据复核误拦截/误通过；
  3. 收集匿名不适感问卷；
  4. 记录问题、责任人与修复截止日。

## 2. 指标与采集方式

| 指标 | 口径 | 来源 | 频率 |
|---|---|---|---|
| 工时录入耗时 | 从开始录到提交的秒数，按人日抽样 | 现场计时/操作录屏（仅自愿） | 每周 |
| 语音确认率 | confirmed / 窗口内全部录音 | `pilot-g4-metrics.sql` | 每周 |
| 周报提交率 | 已提交人周 / 应提交人周 | 同上 | 每周 |
| 周报修改率 | version>1 的已提交周报 / 已提交周报 | 同上 | 每周 |
| 预审自动通过率 | `post_actor_kind='ai'` 的入账单 / 全部入账单 | 同上 | 每周 |
| 误拦截率 | 人工复核通过数 / 人工复核总数，作为代理指标；周会抽样确认真实误拦截 | 同上 + 抽样 | 每周 |
| 人工复核时效 | 复核时间 − 单据创建时间，平均小时 | 同上 | 每周 |
| 员工不适感 | 匿名问卷 1–5 分，含隐私担忧与操作负担 | 问卷 | 每周 |

首周只建立基线，不与目标值比较；第二周起看趋势与异常点，不追求单周数字好看。

运行方式：

```powershell
wsl -d pglab -e su postgres -c "psql -d platform -f /mnt/d/Projects/temp_20261109_01/scripts/pilot-g4-metrics.sql"
```

默认窗口为最近四个完整自然周；试点期间固定每周一跑一次上一周数据。

## 3. 每周复核议程

1. 上周指标与环比，标出异常波动。
2. 误拦截清单：规则码、单据、人工结论、是否补规则或补样本。
3. 误通过清单：抽样中发现的人工放行但应拦截的情况。
4. 隐私与权限：是否有越权尝试、导出是否只含本人数据、供应商开关是否符合预期。
5. 员工反馈：录音是否尴尬、确认步骤是否繁琐、周报是否仍需大改。
6. 行动项：负责人、截止日、下周验证方式。

暂停条件（任一命中立即暂停试点并上报）：

- 出现跨租户或越权访问；
- 语音、OCR 原文或导出文件泄露到非授权方；
- 已入账单据被非预期修改或删除；
- 员工明确表示因隐私顾虑不愿继续。

## 5. Phase 4 退出标准映射

- 员工可纯语音或纯文字完成工时：用 W2–W4 的实际提交记录与访谈确认。
- 周报数字与工时逐项可回溯：抽查周报来源映射与日快照一致。
- 单据规则 + OCR 全通过可自动入账，异常必转人工：用自动通过率与抽样复核确认。
- 全程无设备监控与屏幕采集：以隐私说明、代码边界与员工访谈三方交叉确认。
- G4 证据批准：本目录材料齐备且三方签字完成。

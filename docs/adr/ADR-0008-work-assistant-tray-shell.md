# ADR-0008 工作助手托盘外壳与本地安全存储

| 项目 | 内容 |
|---|---|
| 状态 | **已废弃（Superseded）**：2026-11-13 需求变更，取消 Windows 托盘客户端与本地采集缓存 |
| 日期 | 2026-11-11（2026-11-13 标注废弃） |
| 依据 | `PLAN.md` §3.7、§11.5；`docs/adr/ADR-0006-desktop-collection-boundary.md`；`IMPLEMENTATION_PLAN.md` Phase 4 需求变更说明 |
| 影响 | 原 WP01-05、Phase 4 工作助手试点、Phase 10 发布 |

## 1. 决策

1. **本工作包的托盘外壳使用 WinForms（.NET 8 内置 `NotifyIcon`）**，不引入 Windows App SDK、WinUI 3 或第三方托盘组件。
2. 壳层只负责展示与把用户操作转成状态机调用。状态机、策略、上传门禁、离线队列、签名与更新回滚全部放在 `WorkAssistant.Core` / `Storage` / `Device` 三个可无界面测试的库中；壳层不持有采集开关的独立副本。
3. 采集提示窗在 `Capturing` / `Paused` / `PrivateMode` 三种状态下置顶显示且不可关闭；菜单不提供隐藏提示、隐藏托盘或静默运行项。
4. 本地缓存使用 DPAPI `CurrentUser` 加密（附加熵含 `device_id`）；离线队列原子写入、按到期时间删除、崩溃后一律回到 `Stopped`，绝不自动恢复采集。
5. 设备私钥为 ECDSA P-256，按 ADR-0006 执行；请求签名编码统一为 IEEE P1363，服务端用 `SHA256withECDSAinP1363Format` 验证。

## 2. 理由

- WinUI 3 没有内置托盘图标，需要 `H.NotifyIcon` 一类第三方组件；骨架阶段引入它只会增加供应链与构建风险，且托盘行为仍需单独自测。
- 托盘与提示窗是 Windows 原生能力，WinForms 在 `windows-latest` 上无需额外工作负载即可构建，符合 CI「警告即错误」的现有门禁。
- 把全部隐私与状态逻辑放在无 UI 的库中，才能让「未开始/暂停采集量为 0」「提示可见」「撤销后不能上传」由控制台自检与真实链路脚本自动证明，而不是依赖人工看界面。

## 3. 被否决的方案

| 方案 | 否决理由 |
|---|---|
| WinUI 3 + H.NotifyIcon | 额外 SDK 与第三方依赖；骨架阶段收益低，构建与供应链风险高 |
| 托盘壳直接持有采集状态与上传逻辑 | 无法在 CI 中验证隐私边界，UI 重构会重新引入绕过路径 |
| 采集提示允许用户/管理员关闭 | 违反 PLAN §11.5「采集状态必须持续可见」 |
| 用普通文件缓存离线片段 | 终端被攻陷时可直接读取原始内容，违反 ADR-0006 的 DPAPI 要求 |

## 4. 后果

- 托盘外观与 Windows 11 原生风格存在差异，Phase 4 若改为 WinUI 3，只替换壳层，`Core`/`Storage`/`Device` 的接口保持不变。
- WinForms 项目目标框架为 `net8.0-windows`，其余库保持 `net8.0`，便于无界面测试。
- DPAPI 绑定当前 Windows 用户：换用户或重装系统后本地缓存不可解密，按失败即拒绝处理（队列条目进隔离区，不尝试恢复明文）。
- 设备 ID 由 `MachineGuid + tenant_id` 派生；系统重装后视为新设备，旧设备需由管理员撤销。

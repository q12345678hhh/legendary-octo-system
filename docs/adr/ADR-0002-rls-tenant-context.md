# ADR-0002 租户上下文与 RLS 执行方式

| 项目 | 内容 |
|---|---|
| 状态 | 已接受（尖峰 A 验证后） |
| 日期 | 2026-11-09 |
| 依据 | `docs/spikes/spike-A-rls.md`、`PLAN.md` §6.4、§7.1、§9 |
| 影响 | WP01-03、WP02-01、所有租户表 |

## 1. 决策

1. 数据库角色三分离：`migrator`（超级用户，仅迁移）、`owner`（非超级用户，持表）、`app`（非超级用户，应用连接）。
2. 所有租户表同时启用 `ENABLE` 与 `FORCE ROW LEVEL SECURITY`。
3. 策略统一写作：
   `tenant_id = nullif(current_setting('app.tenant_id', true), '')::uuid`
4. 租户上下文只允许通过 `SET LOCAL app.tenant_id = ...` 在事务内设置。
5. 连接归还池前执行复位；禁止依赖连接池自动清理会话变量。
6. 无上下文的查询返回空集是预期行为，后台任务必须显式建立上下文。

## 2. 理由

| 决策 | 证据 |
|---|---|
| 运行角色非超级用户 | 超级用户 + FORCE 仍可见 3 行（CONTROL 1） |
| 必须 FORCE | 非超级用户所有者取消 FORCE 后可见 3 行（CONTROL 3） |
| 必须 `nullif` | `RESET` 后裸 `''::uuid` 抛 `invalid input syntax`，硬化后返回 0 行（CASE 5） |
| 必须 `SET LOCAL` | 事务内 `SET` 提交后仍残留，池化下越权可见 2 行（CASE 6） |

## 3. 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 依赖应用层 `WHERE tenant_id = ?` | 一处遗漏即全表可见；无法防御 SQL 注入或新开发者遗漏 |
| 每个租户一个 schema | 迁移成本随租户数线性增长，跨租户报表困难，PLAN 已选共享库 |
| 运行角色用超级用户 + 仅靠策略 | 超级用户绕过策略，等于没有隔离（CONTROL 1） |
| 会话级 `SET` + 连接池 | 已验证会跨请求泄漏（CASE 6） |

## 4. 后果

正面：隔离由数据库强制，应用层遗漏不会导致越权；测试可用负例证明。

负面与代价：

- 每个请求必须包在事务里，否则 `SET LOCAL` 无意义——这会影响只读查询的实现方式。
- 后台任务、定时作业、迁移脚本都需要显式上下文入口，否则静默读不到数据。
- 表数量增长时，策略需随建表模板自动生成，不能手工维护。

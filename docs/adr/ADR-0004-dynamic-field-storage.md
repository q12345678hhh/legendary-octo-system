# ADR-0004 动态字段存储模型

| 项目 | 内容 |
|---|---|
| 状态 | 已接受（尖峰 B 验证后） |
| 日期 | 2026-11-09 |
| 依据 | `docs/spikes/spike-B-dynamic-fields.md` |
| 影响 | WP03 部门工作区、WP05 低代码、WP11-01 导入、WP03 汇报 |

## 1. 决策

1. 模块实例数据存 `jsonb`，字段定义（类型、必填、校验、选项）存关系表，二者分离。
2. 索引策略：列表页用 `(tenant_id, created_at desc)`；被设为筛选条件的字段按需建表达式索引（`(data->>'fXX')`）或使用 GIN；索引数量设上限并定期回收。
3. 报表类查询走预聚合表或物化视图，不允许实时全量聚合。
4. EAV 不作为模块数据主路径；仅在需要跨模块字段统一治理的特定场景评估使用。

## 2. 理由

| 决策 | 证据 |
|---|---|
| JSONB 存实例 | Q2 快 347×、Q3 快 46×、存储少 6.3×（86.7→0.25 ms、100.4→2.2 ms、428→68 MB） |
| 索引按需 | 稀疏条件下 JSONB 也会退化，必须由平台按筛选字段建索引 |
| 聚合预计算 | 10 万条实时聚合 32 ms，量级上去不可接受 |
| 不用 EAV 主路径 | 200 万行导致迁移/备份/VACUUM 成本放大约 6 倍 |

## 3. 被否决的方案

| 方案 | 否决理由 |
|---|---|
| EAV（field_value 表） | 多字段筛选退化为全表扫描，存储与维护成本高 |
| 每模块一张物理表 + 动态 DDL | 迁移不可控，字段变更需锁表，多租户下 DDL 数量爆炸 |
| 纯 GIN 无额外索引 | 聚合与范围查询仍慢，且 GIN 写放大明显 |
| 全部字段建索引 | 索引数量与写入成本失控，需按筛选频率取舍 |

## 4. 后果

- 字段类型校验、唯一性约束需在应用层实现（JSONB 无法表达跨行唯一约束），需要明确一致性的兜底。
- 索引由平台自动创建，必须有上限与回收机制，否则长期运行后写入变慢。
- 报表需求若提前出现，需要先建预聚合，不能直接查明细。

# ADR-0007 AI 工具授权与审批基线

| 项目 | 内容 |
|---|---|
| 状态 | 已接受（尖峰 E 验证后） |
| 日期 | 2026-11-09 |
| 依据 | `docs/spikes/spike-E-ai-tool-permissions.md` |
| 影响 | WP10 AI 平台、WP05 审批、WP11 脱敏与 DLP、G6/G8 门禁 |

## 1. 决策

1. AI 的每一次工具调用都必须经过服务端六层顺序判定，任何一层拒绝即终止：

   | 层 | 规则 | 拒绝原因 |
   |---|---|---|
   | 1 | 工具在注册表内 | `unknown_tool` |
   | 2 | 工具在 AI 主体的委托白名单内 | `not_delegated` |
   | 3 | 工具所需数据域已授予主体 | `data_scope_denied` |
   | 4 | 参数字段集合与工具定义完全一致 | `invalid_params` |
   | 5 | 高风险工具具备绑定参数的审批 | `approval_*` / `separation_of_duties` |
   | 6 | 出站内容通过 DLP | `dlp_blocked` |

2. **权限不来自提示词**：模型输出只被当作「意图」，不构成授权来源。注入内容只能改变意图，不能改变委托、数据域与审批要求。
3. 审批对象必须绑定 `tool + args_fingerprint + approver + expiry`，执行时重算比对；批准人不得是执行人。
4. 幂等键 = `sha256(principal + tool + canonical(args))`；重复执行返回原回执，不产生第二个副作用。
5. 每轮工具调用有上限；每个 allow 产生回执，每个 deny 记录原因与 correlation_id。
6. 进入模型前的文本必须先脱敏；出站工具的正文独立再过一次 DLP，审批不豁免。

## 2. 理由

尖峰 E 用确定性模型桩模拟「已被注入说服」的模型，14 项断言全部成立：注入要求调用未委托的 `update_salary` 与 `export_report`，两者都被第 2 层直接拒绝；即便拿到合法审批，正文带身份证号的邮件仍在第 6 层被拦。

这说明控制面可以独立于模型鲁棒性成立。反过来，如果把安全性押在「模型不会被说服」上，就永远无法给出可测的验收证据——这正是 PLAN 评审重点 5 要求的能力。

## 3. 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 依赖系统提示词约束 AI 行为 | 提示词可被间接注入覆盖，且无法给出确定性测试证据 |
| 让 AI 用高权限数据库账号，靠 SQL 层过滤 | 违反 PLAN「AI 不直接访问数据库」；一次注入即可绕过全部业务规则 |
| 审批只记录「已批准」不绑定参数 | 批准 A 执行 B 是典型绕过路径（尖峰 E 第 6 项即此场景） |
| 出站内容靠审批把关，不做 DLP | 审批人无法逐字核验正文；敏感数据外发必须是机器拦截 |
| 幂等键用时间戳或随机数 | 重试必然重复执行，无法满足 PLAN 评审重点 3 |

## 4. 后果

- 工具注册表成为强约束：新增工具必须同时定义风险等级、数据域与参数结构，否则无法注册。
- 审批系统需要支持「参数指纹」而非仅「同意/拒绝」，审批 UI 必须展示被批准的精确参数。
- DLP 是独立演进组件，需要规则版本化与误报率观测，不能硬编码在业务里。
- 模型侧鲁棒性仍需真实端点评测（尖峰 E2），本 ADR 不为其背书。

## 5. 落地检查项

- [ ] WP10 实现六层判定并保留 14 项断言为回归用例。
- [ ] WP05 审批对象增加 `args_fingerprint`，审批详情页展示精确参数。
- [ ] WP02 审计表改为不可变（仅追加）并定义保留期与查询接口。
- [ ] WP10 委托支持 TTL 与任务结束回收。
- [ ] WP11 脱敏服务独立部署，规则版本化，覆盖姓名/地址/金额/附件。
- [ ] 尖峰 E2：接入真实模型端点后补抗注入评测集，与控制面断言分层报告。
